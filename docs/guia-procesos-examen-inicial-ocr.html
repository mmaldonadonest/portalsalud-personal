1 · Mapa general

Cuatro actores: OCR manda candidatos y recibe el dictamen; médico captura en el portal; portal guarda, avisa y reintenta; y el almacén es el biométrico (WS ORDS Servcio/Medico para el examen, tablas SERV_MED_* dentro de BIOMETRICO para todo lo demás).

2 · Solicitud desde OCR

OCR crea la solicitud; el portal valida, guarda y avisa al servicio médico. El candidato normalmente no existe en el biométrico: la solicitud hace de ficha.

sequenceDiagram
  autonumber
  participant OCR
  participant F as OcrTrazaFilter → OcrApiKeyFilter
  participant C as OcrSolicitudController
  participant S as SolicitudExamenService
  participant BD as SERV_MED_EXAMEN_SOLICITUD
  participant N as Notificaciones
  OCR->>F: POST /solicitudes (JSON + X-Api-Key)
  Note over F: traza completa en logs/portal-salud-ocr.log
  alt sin llave en el WAR
    F-->>OCR: 503 NO_DISPONIBLE
  else llave mala o ausente
    F-->>OCR: 401 NO_AUTORIZADO
  end
  F->>C: pasa
  C->>S: crear(body)
  S->>S: 7 obligatorios: nss, nombre, apellidos, curp, puestoSolicitado, cuenta
  alt faltan o mal formados
    S-->>OCR: 400 SOLICITUD_INVALIDA + detalles[]
  end
  S->>BD: ¿existe referenciaOcr?
  alt ya existía
    S-->>OCR: 200 (misma solicitud, idempotente)
  end
  S->>S: candado(nss): ¿empleado con examen vigente?

4 · Dos usuarios sobre el mismo examen

El primero que abre el examen de una solicitud queda como atendiendo (ATENDIDO_POR / ATENDIDO_AT). Otro usuario puede verlo, pero no finalizarlo hasta que lo tome.

sequenceDiagram
  participant A as Médico A
  participant B as Médico B
  participant P as Portal
  A->>P: abre examen inicial del NSS
  P->>P: asignarSiLibre → ATENDIDO_POR = A
  B->>P: abre el mismo examen
  P-->>B: banner ámbar "Lo está atendiendo A desde las 10:32" + botón Tomar examen
  B->>P: Finalizar
  P-->>B: 400 "Este examen lo está atendiendo A…"
  B->>P: Tomar examen (confirmación)
  P->>P: reasignar → ATENDIDO_POR = B (auditado)
  P-->>B: shell recargado sin banner
  A->>P: Finalizar
  P-->>A: 400 "Este examen lo está atendiendo B…"
También se puede Tomar desde la bandeja sin abrir el examen. El borrador es uno solo por NSS: lo que A capturó lo ve B. No hay bloqueo de edición, solo de finalización.

5 · Finalizar y aviso a OCR (webhook)

Finalizar es la única acción que escribe en el biométrico. El webhook no se manda en línea: se programa y un proceso lo envía y reintenta.

sequenceDiagram
  autonumber
  participant M as Médico
  participant E as ExamenInicialService
  participant WS as WS Servcio/Medico + SERV_MED_TAG
  participant H as SERV_MED_EXAMEN_HISTORICO
  participant S as SolicitudExamenService
  participant W as OcrWebhookService (cada 60 s)
  participant OCR
  M->>E: Finalizar (dictamen + diagnóstico ICD + firma)
  E->>E: candado + "¿me lo asignaron a mí?"
  E->>WS: examen completo tipo Admisión
  E->>H: registrar(origen INICIAL, dictamen)
  E->>E: cerrar borrador (queda FINALIZADO)
  E-->>M: abre el expediente impreso en pestaña nueva
  E-)S: evento ExamenInicialFinalizado(nss, dictamen)
  S->>S: solicitud → FINALIZADO (dictamen, fechaExamen, historicoId)
  S->>W: programar envío intento 1 (SERV_MED_INTEGRACION_ENVIO)
  loop cada 60 s
    W->>OCR: POST callback · X-Firma = HMAC-SHA256(cuerpo)
+ X-Firma-Tiempo, X-Firma-V2, X-Evento
    alt 2xx
      OCR-->>W: {"recibido": true}
      W->>S: NOTIFICADO_AT
    else error / sin respuesta
      W->>W: FALLO → reprograma +1, +5, +15, +60, +360 min
      Note over W: tras 6 intentos → AGOTADO (Admin › Reenviar)
    end
  end

6 · Estados

Solicitud (SERV_MED_EXAMEN_SOLICITUD.ESTATUS)

stateDiagram-v2
  [*] --> PENDIENTE: OCR crea (201)
  PENDIENTE --> EN_CAPTURA: médico abre el examen
  PENDIENTE --> CANCELADO: OCR cancela / caducidad (01:15, caduca < hoy)
  EN_CAPTURA --> CANCELADO: OCR cancela / caducidad
  EN_CAPTURA --> FINALIZADO: Finalizar
  PENDIENTE --> FINALIZADO: Finalizar (sin pasar por EN_CAPTURA)
  FINALIZADO --> [*]
  CANCELADO --> [*]

Envío del webhook (SERV_MED_INTEGRACION_ENVIO.ESTATUS)

stateDiagram-v2
  [*] --> PENDIENTE: programado (intento n)
  PENDIENTE --> OK: OCR respondió 2xx
  PENDIENTE --> FALLO: error HTTP / red → se programa intento n+1
  PENDIENTE --> AGOTADO: falló el 6º intento
  AGOTADO --> PENDIENTE: Admin › Reenviar
  OK --> PENDIENTE: Admin › Reenviar (manual)

Borrador del examen (SERV_MED_EXAMEN_BORRADOR)

Uno por NSS: abierto mientras se captura → FINALIZADO al terminar (se conserva como histórico de la captura). Un nuevo examen inicial del mismo NSS abre otro borrador.

flowchart TD

El candado se evalúa al crear la solicitud (409 a OCR), al abrir el shell (banner rojo, Finalizar deshabilitado) y otra vez al finalizar (por si cambió en medio).
